# Self-Updating Desktop Application

Alpha Premier Attendance uses Tauri v2's official native updater plugin (`tauri-plugin-updater` and `@tauri-apps/plugin-updater`) to check GitHub Releases (`Deign86/alpha-premier-attendance`) for signed application updates and install them seamlessly without manual installer downloads.

---

## 1. Overview & Architecture

```text
GitHub Tag (e.g. v0.1.15)
       │
       ▼
GitHub Actions (release.yml) ──► Builds NSIS installer & signs with Ed25519 private key
       │
       ▼
GitHub Releases ──► Publishes latest.json manifest + signed NSIS bundle (*.nsis.zip)
       │
       ▼
Alpha Premier Desktop Kiosk ──► Periodic background check or System Tray / Admin trigger
       │
       ▼
In-App Update Modal ──► Downloads, verifies Ed25519 signature, installs, & relaunches
```

---

## 2. Signing Keypair Generation & Security

Tauri updater packages are signed with an Ed25519 minissign keypair. The public key is embedded in `src-tauri/tauri.conf.json` and the private key is held strictly as a secret in GitHub Actions.

### Generating a New Signing Keypair (if ever needed)

```powershell
npx @tauri-apps/cli signer generate -w src-tauri/tauri.key
```

This outputs:
1. **Private key** saved to `src-tauri/tauri.key` (or output in terminal with password).
2. **Public key string** (e.g. `dW50cnVzdGVkIGNvbW1lbnQ6...`).

> **SECURITY NOTE**: Never commit `*.key` files or private key text to Git. The `.gitignore` is configured to exclude `*.key`, `*.key.pub`, and `tauri-keys/`.

### Configured Public Key

The public key is configured in `src-tauri/tauri.conf.json`:

```json
"plugins": {
  "updater": {
    "pubkey": "dW50cnVzdGVkIGNvbW1lbnQ6IG1pbmlzaWduIHB1YmxpYyBrZXk6IDY2Qjg3Mzc4M0M5QUU5NjMKUldSajZabzhlSE80WnU4YzJDMjUyeEc2eUY1NWtOdXpGV0s2RGJCd0JpODlDb2hwaUJEMkFJMGYK",
    "endpoints": [
      "https://github.com/Deign86/alpha-premier-attendance/releases/latest/download/latest.json"
    ]
  }
}
```

## 3. GitHub Actions CI Secrets

For automated builds and signed release manifest publishing, configure the following secrets in the GitHub repository (`Settings` → `Secrets and variables` → `Actions`):

| Secret Name | Description |
|---|---|
| `TAURI_SIGNING_PRIVATE_KEY` | The raw private key string generated by `tauri signer generate`. |
| `TAURI_SIGNING_PRIVATE_KEY_PASSWORD` | The password chosen when generating the private key (or empty if none). |

The `.github/workflows/release.yml` workflow automatically signs the Windows NSIS bundles, generates the `latest.json` manifest with signatures and download URLs, and attaches them to the new GitHub Release.

## 4. Cutting a New Release

To release a new version of Alpha Premier Attendance:

1. Update the version numbers in:
   - `package.json` and `client/package.json`, `server/package.json`, `shared/package.json`
   - `src-tauri/Cargo.toml` (`version = "0.1.15"`)
   - `src-tauri/tauri.conf.json` (`"version": "0.1.15"`)

2. Commit and tag:
   ```powershell
   git add .
   git commit -m "chore: bump version to v0.1.15"
   git tag v0.1.15
   git push origin main --tags
   ```

3. The GitHub Actions release workflow will trigger on the `v*` tag, build the desktop app on `windows-latest`, sign the installer, and publish `latest.json` alongside the setup assets on GitHub Releases.

## 5. Kiosk Terminal Pinning & Auto-Update Disable

For kiosk machines at the front desk that must stay pinned to a known-good release:

### Option A: In-App Admin Settings
1. Open the app and navigate to **Admin** → **Data and backup**.
2. In the **Software updates** card, uncheck **"Automatically check for updates on this kiosk terminal"**.
3. Automatic background checks are disabled locally in browser storage. Manual update checks from the admin panel and system tray remain available.

### Option B: Terminal Environment Variable
Set the environment variable on the front-desk Windows machine:
```powershell
[System.Environment]::SetEnvironmentVariable('ALPHA_PREMIER_DISABLE_AUTO_UPDATE', '1', 'Machine')
```

### Option C: `config.toml` Setting
In `$env:APPDATA\com.alphapremier.attendance\config.toml`:
```toml
[updater]
enabled = true
auto_check = false
check_interval_hours = 8
```

## 6. Offline Handling & Resilience

- **Fail Silent**: Background update checks run silently without displaying modal popups or error alerts if the network or GitHub is unreachable.
- **Non-Blocking**: RFID scanning and attendance logging are 100% local (SQLite) and continue functioning normally regardless of update check status.
- **Rollback Safety**: Full database snapshots and pre-restore backups are preserved during and across updates.
